# 模块四：记忆小模型联动与课设评测设计（方案 A）

本文档专门承接《计算机应用综合实习任务书》中最核心的评分项：**“构建适应选择主题的小模型，与大模型联动调优适配，下载公开数据集验证，并测试分析大模型和小模型各自的优势与不足”**。

---

## 1. 为什么个人记忆系统必须有“小模型联动”？

在没有小模型的纯大模型聊天端中，想实现长期记忆只有两条笨路，都有明显硬伤：

| 纯大模型方案 | 做法 | 核心痛点（大模型短板） |
| :--- | :--- | :--- |
| **做法 1：全量塞历史上下文** | 把过去所有聊天记录全拼进 Prompt | 上下文迅速膨胀，Token 消耗成倍增长，首字延迟变慢，且长上下文中间信息容易出现“Lost in the Middle”遗忘现象。 |
| **做法 2：每轮对话都调大模型抽记忆** | 用户每发一句话（哪怕是“哈哈”“好的”“帮我写个快排”），都在后台请求一次大模型判断要不要记笔记 | 日常聊天中 **70%～85% 的话轮根本不含个人长期信息**！每轮硬调大模型不仅浪费 API 调用次数和延迟，大模型还极易“过度脑补”，把一次性问题乱记成长期偏好（记忆污染）。 |

**方案 A（MemoryChat 大小模型协同方案）的分工哲学**：
- **小模型做“高频、窄域、毫秒级守门与检索”**：
  1. **自训小模型 ① `MemoryGate`（写入口守门员）**：每轮对话后先用本地几兆到几十兆的分类小模型在 `< 5ms` 内判断这句话含不含个人记忆价值，直接拦截掉 70%+ 的无效闲聊与纯工具性提问；
  2. **检索小模型 ② `bge-small-zh-v1.5`（读入口导航员）**：发消息前在 `< 3ms` 内从成百上千条历史记忆中精准捞出最相关的 Top-5 片段；
- **大模型做“低频精细提炼与深度语义对话”**：只在 `MemoryGate` 放行后才调用大模型做复杂的指代消解、冲突合并（`ADD/UPDATE`）以及最终的个性化自然语言回复。

## 2. 自训小模型 `MemoryGate` 详细设计

### 2.1 任务定义（三分类）

输入当前用户话轮文本（可选拼接上一句助手提问简短上下文，如 `助手问：你平时用什么语言？ | 用户答：Python 居多`），输出三个类别的概率分布：

- **`0: skip`（无需长期记忆）**：日常寒暄（“早安”“谢谢”）、纯客观知识问答（“TCP 三次握手是什么”）、一次性指令（“帮我润色这段话”）、或明确描述无关他人的事情。
- **`1: profile`（长期核心画像与稳定偏好）**：身份职业、专业背景、长期喜恶、沟通与代码风格偏好（如“我是大四计科学生”“我写代码不喜欢加废话注释”）。
- **`2: episodic`（阶段性事项与个人情景动态）**：近期计划、正在推进的任务、生活状态变化（如“下周三我要交综合实习报告”“最近在准备考研复试”）。

判定门控规则：当 $\max(P_{\text{profile}}, P_{\text{episodic}}) \ge \tau$（默认阈值 $\tau = 0.55$，可在开发集扫描最优 F1 点校准）时放行进入大模型提炼管线，否则直接判定为 `skip`。

### 2.2 双模型训练与对照架构（让课设报告更丰满）

为了在实习报告中深入对比不同体量小模型的特性，训练脚本 `ml_experiments/train_memory_gate.py` 同时实现并对比以下两种小模型（共享完全相同的推理接口 `predict(text) -> {label, confidence, probs}`）：

1. **轻量统计特征小模型 `MemoryGate-LR`（默认随库极速运行）**
   - **结构**：`TfidfVectorizer`（字符级 `1–3 gram` + `jieba` 词级特征拼接，`sublinear_tf=True`）+ `LogisticRegression(class_weight='balanced', C=2.0)`。
   - **亮点**：训练仅需 **2～3 秒**，模型文件 `< 5 MB`，纯 CPU 推理耗时 **`< 1 ms`**，且线性权重高度可解释（可直接导出权重最高的前 20 个触发词展示在报告中，如 `我平时`、`我习惯`、`我是`、`最近在`）。
   - **局限**：面对复杂否定或第三人称转述（如“我室友平时习惯早起，但我起不来”）时，局部词袋特征容易混淆主体。
2. **轻量预训练微调小模型 `MemoryGate-RBT3`（深度学习对照版）**
   - **结构**：选用哈工大讯飞联合实验室开源的超轻量 3 层中文预训练模型 `hfl/rbt3`（参数量仅约 `38M`，远小于标准 BERT 的 `102M`），接一层线性分类头微调 3～5 个 Epoch。
   - **亮点**：具备双向 Transformer 自注意力机制，能有效理解句法结构与主语归属（区分“我”与“我室友”），在复杂语境下准确率与召回率更高；CPU 单条推理约 `8～15 ms`。
   - **局限**：模型体积约 `150 MB`，捕获长跨度隐晦语义仍不及百亿参数大模型（这正好解释了为什么放行后仍需大模型做最终 `ADD/UPDATE/NONE` 复核！）。

## 3. 公开数据集选取与处理方案（`DuLeMon`）

为严格落实任务书**“下载相关数据集进行大模型的测试和调优等功能的验证和使用”**，选用百度千言公开的中文长程个性化对话记忆数据集 —— **`DuLeMon`（Baidu Persona-Chat Dataset）**。

### 3.1 为什么选 `DuLeMon`？
- **任务 100% 契合**：`DuLeMon` 是专门研究“对话系统如何在多轮聊天中提取并利用用户画像记忆（Persona Memory）”构建的真实中文公开数据集。
- **自带高质量标注**：数据集中的每段多轮对话不仅包含双方发言，还逐句标注了**某句用户发言是否暴露了个人画像信息（Persona Grounding）以及对应的结构化画像陈述句**！无需从零人工编造几千条数据。

### 3.2 数据集构建与划分流程（`ml_experiments/download_dulemon.py`）
1. 下载公开的 `DuLeMon` 训练集/验证集/测试集 JSON 文件并保存在 `ml_experiments/data/`。
2. **样本映射**：
   - 将原数据集中带有 `persona` 标注的用户话轮提取为正样本，按规则与关键词辅助划分为 `1: profile`（身份/属性/长期喜好）与 `2: episodic`（近期动态/计划/经历）；
   - 将原数据集中无 `persona` 标注的日常闲聊话轮，补充少量常见工具型指令问句，构成 `0: skip` 负样本；
   - 按 **8 : 1 : 1** 严格按对话 Session 隔离切分为训练集（约 4,000～6,000 条）、验证集与独立测试集（防止同一段对话跨集泄漏）。

- 自动绘制：**三分类混淆矩阵热力图**、**阈值 $\tau$ 扫描下的 Precision-Recall 曲线**。

### 实验二：大模型 vs “大模型 + 小模型联动”端到端对比实验
抽取 `DuLeMon` 中 50 组长程多轮会话（每组包含多轮铺垫对话 + 后续需要结合用户画像回答的测试提问），跑以下 **3 组对照系统**：

| 对照实验组 | 记忆写入机制 | 记忆读取机制 | 预期实验现象与分析重点 |
| :--- | :--- | :--- | :--- |
| **Group 1：纯大模型（滑动窗口基线）** | 不提取独立记忆 | 仅保留最近 6 轮对话原文 | 早期聊过的个人偏好滑出窗口后即彻底遗忘，跨会话个性化回答准确率最低。 |
| **Group 2：纯大模型全量硬抽（无小模型）** | 每轮对话都调大模型提取记忆 | 把提取出的所有记忆全塞进 Prompt | 个性化准确率高，但 **大模型调用次数激增 100%**，总耗时与 Token 消耗最高，且容易产生冗余/闲聊噪声记忆。 |
| **Group 3：MemoryChat 大小模型联动（本系统）** | **`MemoryGate` 门控初筛** + 命中后大模型精炼 | **`bge-small-zh` 向量混合召回 Top-5** | **用极小的本地算力开销拦截约 70%+ 无效抽取请求**，总 Token 消耗大幅下降 50%～70%，同时保持与 Group 2 持平甚至更干净的个性化问答准确率！ |

> **实习报告“各自优势与不足”总结提纲**（答辩核心得分点）：
> - **小模型优势**：极低延迟（毫秒级）、零 API 费用、本地隐私友好、擅长高吞吐门控过滤与稠密向量相似度粗排；**不足**：世界知识少，难以独立完成跨句指代消解与复杂冲突文本改写。
> - **大模型优势**：上下文理解深、能精准合并冲突偏好并生成自然得体的个性化回复；**不足**：逐轮全量调用成本高、延迟大、长窗口注意力易分散。
> - **联动价值**：小模型守门+导航，大模型精炼+生成，实现**效果、速度与 Token 成本的帕累托最优**。
