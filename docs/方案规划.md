# MemoryChat 方案规划（草案）

## 1. 背景与目标
基于当前描述，MemoryChat 的核心目标是：通过本地化保存用户画像与历史上下文，让对话模型“持续了解用户”，并在此基础上提供可扩展的多功能聊天能力（含 Agent 增强能力）。

## 2. 核心能力拆分
1. **用户画像管理**
   - 存储偏好、身份信息、长期目标（可配置字段）。
   - 支持用户主动更新与模型自动提取补全。
2. **上下文记忆管理**
   - 短期记忆：当前会话关键上下文。
   - 长期记忆：跨会话长期事实与偏好。
   - 检索策略：对话前按相关性召回。
3. **对话编排层**
   - 将用户输入 + 检索记忆 + 系统提示统一组装后请求 LLM。
   - 记录交互结果并回写记忆。
4. **多功能扩展（Agent）**
   - 任务型工具调用（如检索、总结、执行脚本）。
   - 通过统一接口接入新 Agent。

## 3. 建议架构（高层）
- **前端 Chat UI**：输入输出、记忆可视化、配置管理。
- **会话与编排服务**：提示词组装、记忆检索、模型调用。
- **Memory Store（本地）**：用户画像、会话摘要、知识条目。
- **Agent 扩展层**：工具注册、权限控制、执行回传。

## 4. 数据与流程（MVP）
1. 用户发送消息。
2. 系统检索用户画像 + 相关历史记忆。
3. 编排层构造 Prompt 并调用 LLM。
4. 返回响应并提取可沉淀信息。
5. 写入本地记忆（带标签/时间戳/来源）。

## 5. 迭代里程碑
- **M1：可用 MVP**
  - 基础聊天 + 本地记忆读写 + 简单记忆检索。
- **M2：记忆质量提升**
  - 记忆打分、去重、过期策略、人工编辑。
- **M3：Agent 增强**
  - 接入 1~2 个实用 Agent（例如总结、任务执行）。
- **M4：产品化完善**
  - 权限与隐私策略、导入导出、性能优化。

## 6. 关键风险与对策
- **记忆污染（错误信息积累）**：加入置信度与可回滚机制。
- **隐私风险**：默认本地存储，敏感字段加密，显式授权上传。
- **上下文过长成本高**：摘要压缩 + 分层检索策略。
- **Agent 失控调用**：工具白名单 + 执行权限分级。

## 7. 下一步落地建议
1. 先定义最小数据结构（用户画像、记忆条目、会话摘要）。
2. 完成单会话内“检索记忆 -> 生成回复 -> 回写记忆”闭环。
3. 增加记忆管理界面（查看、编辑、删除）以提升可控性。
